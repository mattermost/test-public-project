# e2e-test-stack suite

Playwright checks run against one remote test server from the e2e-test-stack control plane, one job per server.

The workflows use the [toolkit's e2e-test-stack actions](https://github.com/mattermost/mattermost-test-automation-toolkit/tree/main/actions/e2e-test-stack):
`create`, `open`, `logs` and `destroy`. Each run names its batch (`web`; `ios` or `android` for mobile; `dt-ios-v2`, `dt-ipad-v2` or `dt-andr-v2` for mobile v2), and every
action names it too. Each test job opens its own server with `open`, which reads the run's create response and needs
the credentials key but no AWS role. Masked values do not pass between jobs, and the CI role trusts only the two
called files. Mobile and desktop follow the same shape: their existing E2E workflow calls their own two files around
its test matrix.

Each workflow that creates servers takes an `account` input: `prod`, the default and what a push runs, or `dev`. Create,
logs and destroy assume that account's CI role, from the repository variable `E2E_TEST_STACK_ROLE_ARN_PROD` or
`E2E_TEST_STACK_ROLE_ARN_DEV`; by hand, destroy's `account` input names the account the batch was created in. Both accounts register
the same public key for this repository, so `E2E_TEST_STACK_CREDENTIALS_KEY` opens either's secrets.

| File                     | What it checks                                                                                                                                                                                                                                                                                              |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/api.spec.ts`      | Ping, the admin's role, the licence, membership, a post's create, edit, reaction and delete, a password reset email in Inbucket, and Inbucket refusing a request without the mail token                                                                                                                     |
| `tests/services.spec.ts` | Each requested service: MinIO stores and serves an upload; the server's Elasticsearch and LDAP connection tests pass; Keycloak serves the SAML realm the server is pointed at; the server calls the webhook sidecar for a slash command and posts its responses. Skipped when the service was not requested |
| `tests/ui.spec.ts`       | Login refusing a wrong password, and login opening the channel                                                                                                                                                                                                                                              |
| `scripts/gh-api.sh`      | Run by the workflows for GitHub API calls: retries a server, network or secondary rate-limit error, and prints every attempt's error on one line                                                                                                                                                            |

Each run creates its own team, channel and member, named for the run. Retries are off. No trace or video is kept, and
CI writes no HTML report and uploads only failed tests' screenshots: the others record the passwords and tokens.

## Environment

| Variable                           | From the `open` step                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------ |
| `SITE_URL`                         | `site-url`                                                                           |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | `admin-username`, `admin-password`                                                   |
| `MAIL_TOKEN`                       | `mail-token`: Inbucket's HTTP Basic password, user `inbucket`, at `mail-<site host>` |
| `EXPECT_LICENSED`                  | `true` when the batch was created with a licence                                     |
| `EXPECT_SERVICES`                  | The batch's `services`, comma-separated                                              |
| `SERVICE_FACTS`                    | The server's `facts` from `open`'s `instances` output, as JSON                       |

## Server logs

Each run uploads its servers' logs as one artifact, `e2e-test-stack-logs-<batch>-<run attempt>`, kept 14 days, with
every known secret taken out.

A destroy run by hand takes a batch id and its account from a run's create summary, such as
`test-public-project-1234-web-1-a1b2c3`, and uploads the logs of its servers still up as
`e2e-test-stack-logs_<batch id>-<run attempt>`; a batch already gone has none. In another account the batch is not
found, and the run passes with it still up. Only a run started by hand can be
destroyed by hand, by whoever started it, once it has completed; any other batch is left to its run's destroy or to the
reaper at its TTL.

```sh
gh run download <run id> -R mattermost/test-public-project -n e2e-test-stack-logs-web-1 -D logs
```

## Development

Node 26. `npm install` also installs a pre-commit hook that runs `fmt:check` (Prettier), `lint` (ESLint), `tsc` and
[yamllint](https://github.com/adrienverge/yamllint) on the e2e-test-stack workflows (rules in `.yamllint`; yamllint must be installed);
[`e2e-test-stack-check.yml`](../.github/workflows/e2e-test-stack-check.yml) runs the same on pull requests.

```sh
npm install
npx playwright install chromium
SITE_URL=... ADMIN_USERNAME=... ADMIN_PASSWORD=... MAIL_TOKEN=... EXPECT_LICENSED=true npm test
```
